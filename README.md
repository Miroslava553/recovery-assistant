# Ассистент восстановления

Программа следит за тем, как долго и в каком состоянии вы работаете за
компьютером, и предлагает сделать перерыв, когда накапливаются признаки
усталости.

Она смотрит на несколько независимых признаков: сколько времени вы работаете
без остановки, как изменился ваш ритм печати, видит ли камера лицо и куда
направлен взгляд, как ведут себя веки, и что вы сами отвечаете о своём
состоянии по стандартным шкалам. Каждый признак сравнивается с вашей личной
нормой, которую программа собирает за первые несколько дней. Перерыв
предлагается, когда изменения держатся несколько замеров подряд.

Всё считается на вашем компьютере, данные никуда не отправляются.

Работает под Windows: определение блокировки экрана и датчик клавиатуры
опираются на системные вызовы Windows. На других системах программа
запустится, но эти два канала останутся пустыми.

---

## Чего программа не делает

Эти ограничения выбраны намеренно.

Она не является медицинским прибором и не ставит диагнозов.

Она не показывает «усталость 73%». Такой цифры нет, потому что за ней не
стоит проверенная вероятностная модель.

Она не распознаёт личность по лицу.

Она не определяет эмоции по выражению лица. Применение искусственного
интеллекта для вывода эмоций на рабочем месте ограничено EU AI Act, и этот
путь исключён из архитектуры.

Она не строит рейтинг продуктивности и ничего не сообщает работодателю.

В обычном режиме она не сохраняет текст, названия клавиш, скриншоты и видео.

## Что проверено, а что пока нет

Ниже перечислено то, что в программе остаётся предположением. Каждый пункт
можно проверить по коду.

**Глазной канал отключён от решений** (`ocular_decisions_enabled = False`).
Программа измеряет моргания и показывает их в диагностике, но на итоговый
уровень они не влияют: точность распознавания ещё не измерена на размеченных
записях нескольких человек. Канал будет включён в решения после такой
проверки.

**Пороги 45, 70 и 105 минут** взяты из литературы о работе за экраном. Это
отправная точка, границы вашего личного утомления они не описывают.

**Правило «два срабатывания из трёх подряд» и порог отклонения ритма печати
`z = 1.5`** выбраны из соображений устойчивости. На данных они не
подбирались.

**Пять уровней нагрузки** обоснованы тем, как ими пользуются. Полевого
исследования, подтверждающего их границы, не проводилось.

**Калибровка по пяти рабочим дням** и первым двум часам каждого из них
остаётся предположением о том, за какое время складывается личная норма.

Разбор архитектуры и того, как принимались решения: `docs/TECHNICAL_REPORT.pdf`.

## Как запустить

Понадобится Python, рекомендуется версия 3.11.

```powershell
python -m pip install -r requirements.txt
```

Запустите приложение:

```powershell
python assistant_app.py
```

Первые несколько дней программа собирает вашу норму и почти ничего не
советует: сравнивать пока не с чем.

Посмотреть на интерфейс, не включая камеру и датчики, можно в режиме
просмотра на выдуманных данных:

```powershell
python preview_ui.py
```

Увидеть уведомление, не дожидаясь полутора часов работы, можно в
демонстрационном режиме с ускоренными таймерами:

```powershell
python assistant_app.py --demo
```

Рекомендация появляется в нём по укороченному таймеру и не означает, что
программа что-то обнаружила. Режим нужен только для проверки интерфейса.

Есть также фоновый монитор без интерфейса:

```powershell
python main.py
```

## Тесты

```powershell
python -m unittest discover -s tests
```

Ожидается 210 тестов со статусом `OK`.

## Проверка глазного канала

Это единственный режим, в котором ведётся временная запись видео. Он
запускается вручную, отдельной командой.

```powershell
python ocular_validation.py capture
python ocular_validation.py review "validation_sessions\ИМЯ_СЕССИИ"
python ocular_validation.py report "validation_sessions\ИМЯ_СЕССИИ"
python ocular_validation.py delete-video "validation_sessions\ИМЯ_СЕССИИ"
```

После ручной разметки видео удаляется отдельной командой, остаются числовые
признаки и отчёт.

Протокол сбора данных: `docs/VALIDATION_PROTOCOL.md`.

## Приватность

### Клавиатура

Программа ставит глобальный низкоуровневый перехватчик клавиатуры Windows
(`WH_KEYBOARD_LL`, файл `app_core/typing_activity.py`). Он видит нажатия во
всех программах, а не только в окне ассистента: вы работаете в других
программах, и без этого канал был бы пустым.

Код нажатой клавиши используется один раз, чтобы отнести событие к одной из
трёх категорий: обычный символ, исправление (Backspace или Delete) и всё
остальное, которое не учитывается. После этого код отбрасывается.

В сборщик попадает структура из двух полей: время и категория. Кода клавиши,
символа и последовательности нажатий там нет, поэтому восстановить набранный
текст из этих данных нельзя.

Это тот же системный механизм, которым пользуются программы для слежки.
Проверить, что именно сохраняется, можно по коду: класс `_TypingEvent`
состоит из двух полей, а превращение кода клавиши в категорию происходит в
`GlobalKeyboardTimingSensor._keyboard_procedure`.

Антивирус может ругаться на программу из-за этого перехватчика.

### Остальное

Кадр с камеры существует только в оперативной памяти. Из него извлекаются
геометрические признаки, после чего кадр не сохраняется.

События ввода с флагом `LLKHF_INJECTED` отбрасываются: их порождают другие
программы, а не человек.

Все решения принимаются на вашем компьютере. База данных лежит в `data/` и
является обычным файлом SQLite, её можно открыть и посмотреть, что внутри. В
репозиторий она не попадает.
