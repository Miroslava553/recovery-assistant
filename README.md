# Ассистент восстановления

Локальный прототип мультимодальной оценки рабочей нагрузки за компьютером.

Программа наблюдает за несколькими независимыми признаками (длительность
непрерывной работы, обезличенный ритм печати, присутствие и ориентация лица,
динамика век, самооценка по стандартным шкалам), сравнивает их с персональной
нормой конкретного человека и предлагает восстановительный перерыв, когда
изменения оказываются устойчивыми.

Вся обработка происходит на устройстве. Ничего не отправляется на сервер.

---

## Что это НЕ

Границы заданы намеренно и являются частью проектных решений, а не
недоработкой:

- Это не медицинский прибор и не источник диагнозов.
- Программа не выдаёт «процент усталости». Такой цифры нет и не планируется
  без отдельно доказанной вероятностной модели.
- Она не распознаёт личность по лицу.
- Она не определяет эмоции по выражению лица. Использование ИИ для вывода
  эмоций на рабочем месте ограничено EU AI Act, и этот путь исключён из
  архитектуры сознательно.
- Она не строит рейтинг продуктивности и не отправляет ничего руководителю.
- Она не сохраняет текст, названия клавиш, скриншоты и видео в обычном режиме.

## Что пока не доказано

- **Глазной канал отключён от принятия решений** (`ocular_decisions_enabled =
  False`). Он измеряется и показывается в диагностике, но не влияет на итоговый
  уровень, потому что precision/recall распознавания морганий ещё не измерены
  на размеченных данных нескольких человек.
- Пороги 45 / 70 / 105 минут — прототипные эвристики, а не найденные границы
  человеческого утомления.
- Порог `z = 1.5` для отклонений печати и правило «2 из 3 подряд» не
  валидированы как оптимальные.
- Пять уровней нагрузки функционально обоснованы, но их границы не подкреплены
  собственным полевым исследованием.
- Калибровка «5 рабочих дней × первые 120 минут» — проектная гипотеза.

Подробный разбор архитектуры и истории решений: `docs/TECHNICAL_REPORT.md`.
Принятые архитектурные решения с обоснованием: `docs/DECISIONS.md`.

## Запуск

Рекомендуется Python 3.11.

```powershell
python -m pip install -r requirements.txt
```

Основное приложение:

```powershell
python assistant_app.py
```

Демонстрационный режим с ускоренными таймерами:

```powershell
python assistant_app.py --demo
```

Демо-режим существует только для проверки интерфейса и механизма уведомлений.
Рекомендация в нём появляется по ускоренному таймеру и не означает, что
программа что-то обнаружила.

Фоновый монитор без интерфейса:

```powershell
python main.py
```

## Тесты

```powershell
python -m unittest discover -s tests -v
```

Ожидается 113 тестов со статусом `OK`.

## Валидация глазного канала

Единственный режим, в котором ведётся временная запись видео. Запускается
явно и вручную.

```powershell
python ocular_validation.py capture
python ocular_validation.py review "validation_sessions\ИМЯ_СЕССИИ"
python ocular_validation.py report "validation_sessions\ИМЯ_СЕССИИ"
python ocular_validation.py delete-video "validation_sessions\ИМЯ_СЕССИИ"
```

После ручной разметки видео удаляется отдельной командой; остаются только
числовые признаки и отчёт.

Протокол сбора данных: `docs/VALIDATION_PROTOCOL.md`.

## Структура

```

tests/                   автоматические тесты
demos/                   отдельные демонстрации сенсоров
docs/                    отчёт, решения, протокол валидации, архив
```

## Приватность

В обычном режиме:

- кадр камеры существует только в оперативной памяти, из него извлекаются
  геометрические признаки, после чего кадр не сохраняется;
- клавиатура превращается во временные интервалы и статистические категории,
  текст не формируется;
- события ввода с флагом `LLKHF_INJECTED` отбрасываются;
- все решения принимаются локально, база — SQLite в `data/`.
