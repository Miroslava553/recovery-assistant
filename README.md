# Ассистент восстановления

Если вы проводите за компьютером помногу часов подряд, вы наверняка знаете
это состояние: работа вроде идёт, но даётся тяжелее, чем час назад, а
заметить момент, когда пора остановиться, почти невозможно изнутри.

Эта программа замечает такой момент со стороны и предлагает сделать перерыв.

Она смотрит сразу на несколько независимых признаков: сколько времени вы
работаете без остановки, как изменился ваш ритм печати, видит ли камера
ваше лицо и куда направлен взгляд, как ведут себя веки, и что вы сами
отвечаете о своём состоянии по стандартным шкалам. Каждый признак
сравнивается не с усреднённым человеком, а с вашей собственной нормой,
которую программа узнаёт за первые несколько дней работы. Перерыв
предлагается тогда, когда изменения держатся, а не мелькнули однажды.

Всё считается на вашем компьютере. Ничего никуда не уходит.

Работает под Windows: определение блокировки экрана и датчик клавиатуры
опираются на системные вызовы Windows. На других системах программа
запустится, но эти два канала останутся пустыми.

---

## Чего программа не делает

Эти границы выбраны намеренно. Они не пробелы, которые когда-нибудь
закроются, а часть замысла.

Она не является медицинским прибором и не ставит диагнозов.

Она не покажет вам «усталость 73%». Такой цифры нет и не будет, пока за ней
не встанет доказанная вероятностная модель. Круглое число выглядит
убедительно ровно настолько, насколько оно ничем не обеспечено, и вы вправе
ожидать, что вам не будут показывать точность, которой не существует.

Она не распознаёт личность по лицу.

Она не определяет ваши эмоции по выражению лица. Применение искусственного
интеллекта для вывода эмоций на рабочем месте ограничено EU AI Act, и этот
путь исключён из архитектуры сознательно.

Она не строит рейтинг продуктивности и ничего не сообщает вашему
работодателю.

В обычном режиме она не сохраняет ни текст, ни названия клавиш, ни
скриншоты, ни видео.

## Где проходит граница между измеренным и предполагаемым

Дальше идёт список того, что в программе пока остаётся гипотезой. Такие
списки в описаниях встречаются редко, и это как раз повод отнестись к
остальному серьёзнее: каждый пункт отсюда вы можете проверить по коду сами.

**Глазной канал намеренно отключён от решений**
(`ocular_decisions_enabled = False`). Программа измеряет моргания и
показывает их в диагностике, но на итоговый уровень они не влияют, потому
что точность распознавания ещё не измерена на размеченных записях
нескольких человек. Канал вернётся в решения после такой проверки, и ни
днём раньше.

**Пороги 45, 70 и 105 минут являются отправной точкой.** Это разумные
значения из литературы о работе за экраном, а не найденная граница вашего
личного утомления.

**Правило «два срабатывания из трёх подряд» и порог отклонения ритма печати
(`z = 1.5`) выбраны из соображений устойчивости**, а не подобраны как
оптимальные на данных.

**Пять уровней нагрузки обоснованы тем, как ими пользуются**, и пока не
подкреплены собственным полевым исследованием.

**Калибровка по пяти рабочим дням** и первым двум часам каждого из них
остаётся проектной гипотезой о том, за какое время складывается личная
норма.

Если вам интересно, как принимались эти решения и почему именно так,
подробный разбор лежит в `docs/TECHNICAL_REPORT.pdf`.

## Как запустить

Понадобится Python, рекомендуется версия 3.11.

```powershell
python -m pip install -r requirements.txt
```

Запустите приложение:

```powershell
python assistant_app.py
```

Первые несколько дней программа присматривается к вашему ритму и почти
ничего не советует. Это нормально: пока личная норма не сложилась, сравнивать
не с чем.

Если хотите посмотреть на интерфейс, не включая камеру и датчики, откройте
просмотр на выдуманных данных:

```powershell
python preview_ui.py
```

А если хотите увидеть, как выглядит уведомление, не дожидаясь полутора часов
работы, запустите демонстрационный режим с ускоренными таймерами:

```powershell
python assistant_app.py --demo
```

Учтите, что рекомендация появляется в нём по укороченному таймеру и не
означает, что программа что-то обнаружила. Этот режим существует только для
проверки интерфейса.

Есть ещё фоновый монитор без интерфейса:

```powershell
python main.py
```

## Тесты

```powershell
python -m unittest discover -s tests
```

Ожидается 210 тестов со статусом `OK`.

## Проверка глазного канала

Это единственный режим, в котором ведётся временная запись видео, и
запускается он вручную, отдельной командой.

```powershell
python ocular_validation.py capture
python ocular_validation.py review "validation_sessions\ИМЯ_СЕССИИ"
python ocular_validation.py report "validation_sessions\ИМЯ_СЕССИИ"
python ocular_validation.py delete-video "validation_sessions\ИМЯ_СЕССИИ"
```

После ручной разметки видео удаляется отдельной командой, и остаются только
числовые признаки и отчёт.

Протокол сбора данных лежит в `docs/VALIDATION_PROTOCOL.md`.

## Приватность

### Про клавиатуру, честно и сразу

Программа ставит глобальный низкоуровневый перехватчик клавиатуры Windows
(`WH_KEYBOARD_LL`, файл `app_core/typing_activity.py`). Он видит нажатия во
всех программах, а не только в окне ассистента, иначе от этого канала не
было бы никакого толку: вы работаете не в ассистенте.

Код нажатой клавиши живёт ровно одно мгновение. За это время он попадает в
одну из трёх категорий: обычный символ, исправление (Backspace или Delete)
и всё остальное, что не учитывается вовсе. Дальше код отбрасывается.

В сборщик уходит структура из двух полей: время и категория. Ни кода
клавиши, ни символа, ни последовательности нажатий там нет, поэтому
восстановить набранный вами текст из этих данных невозможно.

Механизм здесь тот же самый, которым пользуются программы для слежки.
Отличается не способ чтения, а то, что остаётся после. Убедиться можно
построчно: класс `_TypingEvent` состоит из двух полей, а превращение кода
клавиши в категорию происходит в
`GlobalKeyboardTimingSensor._keyboard_procedure`.

Побочное следствие, о котором стоит знать заранее: ваш антивирус может
ругаться на программу именно из-за этого перехватчика. Так и должно быть.

### Всё остальное

Кадр с камеры существует только в оперативной памяти. Из него извлекаются
геометрические признаки, после чего кадр не сохраняется.

События ввода с флагом `LLKHF_INJECTED` отбрасываются: их порождают другие
программы, а не вы.

Все решения принимаются на вашем компьютере, а база данных лежит в `data/`
и является обычным файлом SQLite. Вы можете открыть её и посмотреть, что там
хранится. В репозиторий она не попадает и никуда не отправляется.
