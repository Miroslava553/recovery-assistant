# Проверка глазного сенсора

Этот режим синхронно записывает локальное диагностическое видео и числовые
сигналы глаз. Затем автоматический детектор сравнивается с ручной разметкой.
До такой проверки пороги морганий не переносятся в рабочий продукт.

## 1. Проверить проект

Открой PowerShell в папке, где расположен `ocular_validation.py`, и выполни:

```powershell
python -m unittest discover -s tests -v
```

Ожидается:

```text
Ran 94 tests
OK
```

## 2. Записать сессию

```powershell
python ocular_validation.py capture
```

### Что видно до записи

Статус `READY - NOT RECORDING`. Файлы в этот момент не создаются.

Начать можно двумя способами:

- щёлкнуть зелёную кнопку `START RECORDING`;
- нажать `Пробел` один раз.

### Как понять, что запись началась

Одновременно появляются:

- красная рамка вокруг изображения;
- красная точка и надпись `REC`;
- стадия `CALIBRATION`, затем `BLINK TEST`;
- растущий `Elapsed`;
- растущий счётчик `samples`;
- красная кнопка `SAVE SESSION`.

### Диагностика пригодности в реальном времени

Панель показывает:

- `Current frame: VALID/INVALID` — пригоден ли текущий кадр;
- `Reject now` — какие критерии текущий кадр не прошёл;
- `Coverage` — доля пригодных кадров;
- `Rejection rates` — накопленные причины браковки.

Причины браковки не взаимоисключающие. Например, один кадр может одновременно
иметь плохой ракурс головы и низкое качество правого глаза. Поэтому проценты
отдельных причин могут суммироваться больше 100%.

Используемые критерии:

- лицо найдено;
- качество изображения не ниже 0.55;
- качество каждого глаза не ниже 0.55;
- качество ракурса головы не ниже 0.35;
- числовой сигнал каждого глаза существует и конечен.

Эти пороги не снижаются автоматически ради красивого процента покрытия.
Сначала выясняется причина браковки.

### Что делать во время записи

1. Во время `CALIBRATION` спокойно смотри на экран с обычно открытыми глазами.
2. После появления `BLINK TEST` сделай не менее 20 обычных морганий.
3. При отдельном тесте можно добавить неполные прикрытия и подмигивания.
4. Нажми `SAVE SESSION` или `Enter`.

`Live blink count: OFF` означает, что число морганий будет рассчитано после
ручной разметки, а не во время записи.

## 3. Что сохраняется

Папка вида:

```text
validation_sessions\20260802_161714
```

содержит:

- `validation_video.avi` — локальное видео для разметки;
- `signals.csv` — покадровые числовые сигналы;
- `metadata.json` — параметры записи;
- `quality_report.txt` — читаемый отчёт о пригодности;
- `quality_report.json` — тот же отчёт в структурированном виде.

Обычный `main.py` видео не записывает.

## 4. Решение после записи

Целевое покрытие этапа `BLINK TEST` — не ниже 85%.

При достаточном покрытии PowerShell напечатает команду `review`.

При низком покрытии программа выводит:

- фактическое покрытие;
- число пригодных и непригодных кадров;
- до пяти главных причин браковки;
- путь к `quality_report.txt`.

Сессию с низким покрытием не используют для настройки детектора. Сначала
исправляют условия съёмки либо ошибку программного критерия и повторяют запись.

## 5. Разметить истинные события

```powershell
python ocular_validation.py review "validation_sessions\ИМЯ_СЕССИИ"
```

Управление:

- `Пробел` — воспроизведение/пауза;
- стрелки — предыдущий/следующий кадр;
- `1` — обычное полное моргание;
- `2` — намеренно неполное моргание;
- `3` — подмигивание левым глазом;
- `4` — подмигивание правым глазом;
- `Backspace/Delete` — удалить ближайшую метку;
- `0` — отменить последнее изменение;
- `Enter` или `Esc` — сохранить и выйти.

Метка ставится на кадре максимального закрытия век.

## 6. Получить отчёт точности

```powershell
python ocular_validation.py report "validation_sessions\ИМЯ_СЕССИИ"
```

Создаются `normalized_signals.csv`, файлы событий, `report.txt`, `report.json`
и `signal_plot.png`.

Главные показатели: precision, recall, F1, ложные события, пропуски, покрытие
сигнала и реальный FPS. Параметры одной сессии не переносятся автоматически в
рабочий продукт.

## 7. Разобрать уже записанную сессию

Для старой сессии повторная запись не нужна. Команда работает без видео и
использует `signals.csv` и `metadata.json`:

```powershell
python ocular_validation.py quality "ПОЛНЫЙ_ПУТЬ_К_ПАПКЕ_СЕССИИ"
```

Например:

```powershell
python ocular_validation.py quality "C:\Users\Admin\Downloads\fatigue_assistant_step3_validation_fixed\fatigue_assistant_step3_validation_fixed\validation_sessions\20260802_161714"
```

Команда создаст `quality_report.txt`, выведет точные причины низкого покрытия и
обновит поля качества в `metadata.json`. Видео для этой операции не требуется.
